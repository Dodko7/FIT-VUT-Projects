# Design Philosophy and Overview
The `parse.py` script is designed to parse SOL25 source code, perform semantic analysis, and generate an XML representation of the abstract syntax tree (AST). The solution leverages the Lark parsing library for efficient syntax analysis and employs a modular approach with separate components for lexical/syntactic parsing, semantic validation, and XML transformation. The script reads from standard input, processes the input, and outputs XML to standard output, adhering to a functional decomposition for clarity and maintainability.

# Internal Representation
The internal representation revolves around a syntax tree generated by Lark based on the `SOL25_GRAMMAR`. This tree is traversed and analyzed using two key classes:
- `SOL25SemanticsVisitor`: A visitor pattern implementation that builds a class hierarchy and tracks scopes, storing data in dictionaries (`self.classes`, `self.builtin_classes`) and lists/stacks (`self.current_blocks`, `self.current_class`).
- `SOL25XMLTransformer`: A transformer pattern implementation that converts the AST into an XML structure using `xml.etree.ElementTree`, with a recursive approach to handle nested constructs.

# Implementation Approach
## Parsing and Grammar
The SOL25 grammar is defined as a raw string (`SOL25_GRAMMAR`) using Lark’s EBNF syntax. It supports class definitions, methods, blocks, and expressions, with terminals like `ID`, `CID` and `SEL` defined via regular expressions to enforce naming rules. Whitespace and comments are ignored using `%ignore WS` and `%ignore COMMENT`.

## Semantic Analysis
The `SOL25SemanticsVisitor` class performs semantic checks:
- **Class Hierarchy**: Validates inheritance, detects circular dependencies using depth-first search (`_check_circular_inheritance`), and ensures `Main` class with a `run` method exists.
- **Scope Management**: Tracks block parameters and variables using a stack (`self.current_blocks`) to detect duplicates or undefined variables.
- **Method Validation**: Verifies method arity and existence, including inherited methods via `_get_all_methods`.

Errors are collected in `self.errors` with exit codes (e.g., 32 for undefined references) and reported in `check()`.

## XML Transformation
The `SOL25XMLTransformer` class transforms the AST into XML:
- **Recursive Transformation**: Methods like `program`, `class_`, and `block` recursively build the XML tree, preserving structure (e.g., `<method>` with `selector` attribute).
- **Expression Handling**: The `_process_expr` method maps tokens (e.g., `INT`, `STR`) to `<literal>` or `<var>` elements and handles method calls with `<send>` elements.

The first comment in the source code is optionally included as a `description` attribute in the `<program>` root.

# Algorithms and Formalisms
The parsing uses Lark’s LALR(1) algorithm for efficiency. Semantic analysis employs a visitor pattern with stack-based scope tracking, while XML generation uses a transformer pattern with recursive descent. The grammar is context-free, with additional semantic rules enforced programmatically.

# Code Structure and Comments
The code is decomposed into:
- `parse_arguments()`: Handles command-line options.
- `SOL25SemanticsVisitor`: Manages semantic validation.
- `SOL25XMLTransformer`: Handles XML output.
- `main()`: Orchestrates the workflow.

Comments in the source code (e.g., `"""Validate block parameters and scope."""`) clarify non-obvious functionality, supplementing descriptive identifiers like `build_selector`.

This implementation ensures a robust, extensible parser for SOL25 with clear separation of concerns and detailed error reporting.
